# 萬春・廟口通｜5 分鐘現場 Demo 腳本

## 0:00–0:35｜問題與定位

「宮廟有人流，但參拜結束後，人潮未必留在附近商圈。萬春・廟口通不是求籤工具；它把萬春宮作為可信任入口，用 LINE 將文化體驗、情境推薦與商圈消費串成可量測的旅程。」

畫面：首頁的 **LINE 生態串連**。

## 0:35–1:20｜LINE 入口與文化信任

「信眾掃廟口 QR Code 後進入 LINE OA。先提供由宮廟核定的參拜與文化預覽，再讓使用者開始規劃行程；不蒐集祈願文字或不必要宗教個資。」

操作：點擊加入 OA 示範狀態，展示 OA 訊息示範，再點 **開始規劃今天的廟口行程**。

## 1:20–2:15｜AI 的工作：受控情境推薦

「使用者選擇今天的目的，例如『參拜後想帶伴手禮』。AI 不自由編造店家或宗教內容，而是依受控的文化、店家與優惠資料，解釋為何推薦這一站。這讓 AI 可用、可控，也能被商圈信任。」

操作：選一個情境，展示推薦理由與優惠。

## 2:15–3:05｜LIFF 身分與雲端領券

「點領券後，LIFF 取得 LINE 身分，伺服器端向 LINE 驗證 ID token，再由 Supabase 雲端發券。同一帳號重複點擊只會拿到同一張券，避免重複發放。」

操作：點 **登入後領取優惠券**，展示雲端券碼。

## 3:05–3:45｜店家一次性核銷

「店家端只保留最少操作：輸入券碼、查驗、確認核銷。核銷在伺服器與資料庫鎖定下完成，同一張券不能重複用。」

操作：切換合作店家，輸入 `0428`，貼上券碼，查驗並確認核銷。

## 3:45–4:30｜商圈營運價值

「店家與地方創生單位看到的不是單次折扣，而是導流漏斗：QR 入口、情境對話、路線查看、領券到核銷。AI 洞察把高轉換情境轉成週末活動與組合券建議。」

操作：展示 **從廟口入口到店家核銷** 漏斗與 AI 情境洞察。

## 4:30–5:00｜商業模式與收尾

「初期由商圈組織、宮廟或地方創生單位訂閱營運；店家可免費加入基本導流。後續才提供置頂曝光、聯合活動與匿名化成效報表等付費服務。萬春・廟口通把一次參拜，轉化為文化理解、商圈消費與可持續營運。」

## 現場備案

- LINE 登入網路不穩：使用已領取的雲端券碼直接展示店家核銷。
- 不展示真實店家／優惠：全程強調資料是競賽示範。
- 不宣稱 LINE Service Message 發送促銷券：優惠與活動回訪由 OA 訊息承接。
